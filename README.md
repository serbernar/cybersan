# cybersan

Головний пристрій (head unit) на Raspberry Pi для **Nissan X-Trail T30**: телеметрія,
медіа та керування в одному повноекранному інтерфейсі.

> Статус: milestone 1 — інтерфейс і контракт даних. Реальних даних з машини ще немає,
> усе працює на записаному циклі руху.

## Що вже є

- **HUD** — React + TypeScript. Дві орієнтації: альбомна 1024×600 (влазить у рамку 2DIN)
  і книжкова 600×1024 (як у Volvo), перемикач у налаштуваннях. Постійна картка авто
  плюс змінна панель контенту, як у Tesla; нижня панель керування завжди на місці.
- **3D-модель авто** — у картці авто крутиться справжній T30 (`apps/hud/public/car/`).
  Модель вирівнюється й масштабується автоматично, перефарбовується в кольори
  теми, фари світяться разом зі справжніми, відчинені двері підсвічуються
  червоним. Кадр малюється лише тоді, коли щось змінилось. Поки модель
  вантажиться — і якщо її прибрати — показується процедурна T30, зібрана кодом
  (`src/components/car/t30.ts`); без WebGL лишається плаский SVG.
- **Демон** — Python 3.11+ / asyncio. Тримає стан автомобіля, роздає зібраний HUD і
  надсилає інкрементальні патчі по WebSocket.
- **Контракт даних** — `packages/protocol`: одна схема, з якої читають і TypeScript, і Python.
- **Bluetooth-медіа** — малина працює як автомобільна магнітола (`NissanT30Companion`,
  клас пристрою «Car audio»). Звук іде через A2DP у PipeWire, а назва треку, виконавець,
  тривалість і позиція приходять по AVRCP через D-Bus. Кнопки на екрані керують плеєром
  у телефоні.
- **Керування живленням** — вмикається з поворотом ключа, вимикається сама через задану
  витримку після того, як ключ вийняли. Утримання живлення робить ядро (`gpio-poweroff`),
  рішення про вимкнення — окрема служба з деба́унсом на прокрутку стартера.
- **Симулятор** — записаний цикл руху, однаковий у браузері й у демоні.

## Структура

```
apps/hud/          React + Vite, збирається на робочій машині
  src/panes/       вміст правої (або нижньої) панелі: vitals, телеметрія, музика, опції
  src/components/  постійні елементи: картка авто, статус-рядок, панель керування
apps/daemon/       Python-демон: стан, джерела даних, WebSocket, роздача статики
packages/protocol/ схема стану + типи (єдине джерело правди)
deploy/            systemd, kiosk-скрипт, встановлення та деплой
docs/adr/          рішення та їх обґрунтування
```

## Розробка

```bash
npm install
npm run dev            # HUD на http://localhost:5173
                       # /model.html — модель авто на весь екран, для підбирання
                       # форми: ?theme=day&beam=1&doors=driver,tailgate
```

Без демона HUD сам вмикає вбудований симулятор і чесно пише про це в статус-рядку.
Щоб примусово: `http://localhost:5173/?sim=1`.

Демон окремо:

```bash
python3 -m venv .venv && .venv/bin/pip install aiohttp
cd apps/daemon && ../../.venv/bin/python -m cybersan --mock
```

Тести демона:

```bash
cd apps/daemon && ../../.venv/bin/python -m unittest discover -s tests -t .
```

## Встановлення на Raspberry Pi

На Pi **не встановлюється** ні Node, ні npm, ні Electron — туди їде лише зібраний
`dist/` і Python-пакет.

```bash
# один раз, на Pi
sudo deploy/install.sh
sudo deploy/bluetooth-setup.sh
sudo deploy/power-setup.sh        # без --enable, поки не зібрана схема запалення

# з робочої машини, після кожної зміни
deploy/deploy.sh
```

Кіоск стартує з `~/.config/labwc/autostart` і відкриває Chromium з `--kiosk --app=…`,
тобто без адресного рядка, вкладок і курсора.

## Джерела даних

| Сигнал | Джерело | Стан |
|---|---|---|
| Оберти, швидкість, температура ОР, впуск, навантаження | OBD-II (ELM327) | заплановано |
| Рівень пального, двері, світло | GPIO / аналогові сенсори | заплановано |
| Координати, висота, курс | GPS | заплановано |
| Трек, виконавець, позиція, керування плеєром | Bluetooth AVRCP | **працює** |
| Стан запалення | GPIO + оптопара | код готовий, чекає на проводку |
| Температура CPU, завантаження, аптайм | система | працює |
| Усе перелічене | записаний цикл руху | працює |

**Важливо про T30 (2001–2007):** у машині переважно K-line (ISO 9141-2 / KWP2000), а не CAN.
Через ELM327 доступні обмеження двигуна — оберти, швидкість, температура, навантаження.
**Рівня пального й стану дверей по OBD там немає** — це окремі сенсори на GPIO.

## Живлення в машині

Дві половини, навмисно незалежні:

1. **Утримання живлення — ядро.** `dtoverlay=gpio-poweroff,gpiopin=17,active_low=1` тримає
   keep-alive пін увесь сеанс і відпускає його в самому кінці halt, коли файлові системи вже
   розмонтовані. Якби пін тримав Python, реле відпускало б у момент падіння процесу — тобто
   рівно тоді, коли цього найменше хочеться.
2. **Рішення вимкнутися — служба `cybersan-power`.** Читає лінію ACC через оптопару і чекає,
   доки запалення буде відсутнє *безперервно* задані секунди. Витримка обовʼязкова: під час
   прокрутки стартера ACC зникає приблизно на секунду, і без деба́унсу магнітола вимикалася б
   при кожному запуску двигуна.

Перевірка перед увімкненням служби, з ключем у руках:

```bash
sudo python3 -m cybersan.power --dry-run --delay 5 --verbose
```

Служба навмисно не вмикається скриптом за замовчуванням: поки оптопара не підключена, пін
читається як «ключа немає», і машина вимикалась би через кілька секунд після кожного старту.
